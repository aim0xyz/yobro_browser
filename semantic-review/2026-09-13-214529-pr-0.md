# Chromium renderer recovery with typed termination and bounded user retry

The implementation adds typed Qt renderer termination, one automatic user-page reload, fail-closed media permission cancellation, and instance/document-bound agent callbacks. Deterministic and real Qt process-kill tests cover the main crash-loop path. Protocol redirects, in-flight profile deactivation, and Qt stale-finish handling still have unsafe state transitions. The permission authority and ABA guards are stronger than the remaining lifecycle gaps.

Watch for: **[High, confirmed]** redirects invalidate their own token-bound agent operation; **[High, confirmed]** profile deactivation misses an in-flight recovery token; **[Medium, likely]** timer-based Qt failure suppression can misclassify a crash or swallow a new load failure; **[Medium, confirmed]** token waits can complete before their `NavigationResult`; **[Medium, confirmed]** recovery state can remain stale after later navigation or explicit agent reload.

**Verdict**: NEEDS_CHANGES

## High-level view

`QtBrowserPage` maps all four Qt termination statuses and completes an active navigation with `rendererTerminated` before publishing the termination event. Generic-failure suppression, however, uses page-global counters and a 50 ms timer instead of the terminated load generation.

`BrowserSession` grants user tabs one automatic same-page reload and renews the budget after a stability interval. Its timers are generation-guarded, but deactivation misses the interval after the recovery task fires and before navigation completes; other navigation outcomes can strand recovery state.

Agent callbacks are bound to tab instance and document epoch, blocking late read/find/action/scroll completions from crossing close/reuse boundaries. Token waits weaken that contract by accepting `loading == false` before the token settles, while redirect URL changes cancel the operation awaiting that token.

Permission capabilities are denied on renderer death, document change, close, profile/surface loss, timeout, and teardown. The material evidence gaps are signal ordering, in-flight profile cancellation, redirects through `BrowserSession`, and real find/action/scroll crashes.

<summary>Issues (8)</summary>

1. **Qt stale-finish ownership — [Medium, likely]** The 50 ms/page-global suppression can consume a new retry’s failure or let a generic failure beat typed termination. Replace it with per-load generations and test active-load death plus immediate retry.
2. **Inactive profile continues recovery — [High, confirmed]** Deactivation ignores an already-started `recoveryToken`, allowing late success and crash-budget reset. Cancel/stop token-bearing recovery and gate stability on profile activity.
3. **Redirect cancels its own `open` — [High, confirmed]** Redirect URL changes invalidate the epoch of the operation awaiting that navigation token. Preserve/rebind token-owning operations and add a protocol redirect test.
4. **Navigation token is advisory — [Medium, confirmed]** Token-bearing waits fall through on `loading=false` before `navigationFinished`. Require the exact result for token waits and test separated state/result delivery.
5. **Stale user recovery status — [Medium, confirmed]** A failed navigation during the stability guard leaves `recovering` with no recovery work, and SpikeWindow masks the error. Close the state transition and prioritize concrete errors in the shell.
6. **Agent reload stays failed — [Medium, confirmed]** Successful explicit reload clears the page error but not agent `rendererRecovery`. Track explicit recovery by token and transition to healthy only on success.
7. **Unbounded agent callbacks — [Medium, confirmed]** Read/find/action/scroll can keep the protocol busy forever if a live renderer never invokes the callback. Add callback-phase deadlines and discard late completions through the existing identity guards.
8. **Race evidence gaps — [Medium, confirmed]** Passing tests omit active-load death, immediate retry, in-flight deactivation, protocol redirects, split state/token delivery, active-token close/teardown, and real non-read callback crashes. Add these as gating deterministic/Qt cases.

<details>
<summary>Details</summary>

### Qt termination typing is guarded by page-global timing state

`QtBrowserPage.cpp:261-301` defers `loadFinished(false)` one event-loop turn, then sets `ignoreFailedFinishAfterTermination_` for 50 ms after `renderProcessTerminated`. `beginNavigation()` at lines 434-443 does not clear or generation-bind that flag; `ignoredSupersededFinishes_` is also a count rather than a load identity.

**[Medium, likely]** A manual or zero-delay retry can start while the 50 ms flag remains set. Its failure is returned early at line 262, leaving the new token unresolved; in the opposite ordering, the deferred generic failure can settle the old token as `navigationFailed` before the typed termination arrives. Replace both heuristics with a load-generation state machine: associate deferred failure and supersession with one generation, suppress only the terminated generation’s stale finish, clear suppression on the next `loadStarted`, and let termination cancel that generation’s pending generic failure. Test an active-load kill followed immediately by manual and zero-delay retries in real Qt.

### Profile deactivation misses an active recovery navigation

The recovery task clears `recoveryTask`, calls `reload()`, and stores `recoveryToken` at `BrowserSession.cpp:872-915`. `setProfileActive(false)` at lines 1604-1618 cancels only `recoveryTask` or `stabilityTask`.

**[High, confirmed]** Deactivation after the timer fires lets reload/network work continue; a late success can schedule stability while inactive and reset the hidden tab’s crash budget. Treat `recoveryToken` or `rendererRecovery == recovering` as cancellable work, invalidate the generation before `stop()`, force `failed`, and require `config.profileActive` both before scheduling and inside the stability callback. Test deactivation after `reloadCount` increments but before completion, then prove a late result cannot restore health; mirror that boundary with real Qt.

### Redirects invalidate the operation that owns them

`navigate()` advances the document epoch and `waitForLoad()` binds the operation to it. After initial load start, every redirect URL change reaches `invalidateDocument()` through `BrowserSession.cpp:762-768`, which pauses the now-stale operation.

**[High, confirmed]** A normal HTTP redirect therefore fails the protocol `open` that initiated it. Preserve a token-waiting operation by rebinding its epoch after redirect invalidation; continue canceling read/find/action/scroll operations, and let a genuinely superseded navigation fail through the original token’s `navigationSuperseded` result. Add a protocol loopback `/redirect` test that expects the final URL and successful correlated response; the direct engine smoke test does not cover this session path.

### Token waits can finish before NavigationResult

Qt publishes `loading=false` before `finishNavigation()` at `QtBrowserPage.cpp:282-288`. `BrowserSession::evaluateWait()` at lines 1024-1040 falls through from a missing expected token to the non-loading continuation, and `maybeResumeWait()` triggers that path at lines 1073-1075.

**[Medium, confirmed]** `open`, `reload`, `back`, and `forward` can respond before their token’s result exists, making token correlation advisory and allowing reentrant work before Qt emits `navigationFinished`. If `waitingToken` is present, return until that exact token appears; use loading state only for no-token readiness waits and return a distinct token timeout. Add a fake that separates `loading=false` from `navigationFinished` and assert no early response.

### Recovery state can outlive the work it describes

A successful automatic reload stays `recovering` during the stability guard. If a new navigation cancels that guard and then fails, it misses the `recoveryNavigation && result.error` branch at `BrowserSession.cpp:929-949`; the tab remains `recovering` with an error and no recovery task. `SpikeWindow.cpp:530-540` prioritizes that stale state over the error.

**[Medium, confirmed]** Make `recovering` require an active task/token/guard and transition a failed navigation during the guard to `failed`. Render `state.error` ahead of a passive recovery label, and do not prefix `rendererRecoveryFailed` with a duplicate “Die Seite wurde beendet.” Test a failed navigation during stability and assert both session state and shell status.

Agent tabs have the inverse stale state: termination sets `failed` at `BrowserSession.cpp:846-849`, but protocol reload at lines 1358-1377 clears only page error, so success never returns `rendererRecovery` to healthy.

**[Medium, confirmed]** Give explicit agent reload its own recovery token: enter `recovering`, become `healthy` only on that token’s success, and stay `failed` on error. Assert `SessionTabView.rendererRecovery` after deterministic and real Qt reloads.

### Correlated agent callbacks have no completion deadline

Read/find/action/scroll callbacks retain tab ID, instance ID, and document epoch, so close, navigation, renderer death, end, and ABA replacement invalidate late completions.

**[Medium, confirmed]** After load readiness, none of those engine calls has a deadline. A live hung renderer or bridge leaves the protocol busy indefinitely; the real Qt test proves recovery only after killing its deliberately hung read. Add a callback-phase timer canceled by completion, retain the identity checks for late callbacks, and cover timeout plus late completion for read, find, action, and scroll.

### Passing evidence omits the disputed interleavings

The targeted build succeeded and all eight configured CTest targets passed. Deterministic coverage includes four termination kinds, one retry, stability reset, crash-loop cutoff, queued close/profile cancellation, permission denial, all four callback crash paths, and read ABA reuse; real Qt covers SIGABRT/SIGKILL, same-object recovery/history, native permission invalidation, hung read failure, and explicit agent reload.

**[Medium, confirmed]** The fake fixes state/navigation/termination ordering, profile cancellation occurs before the recovery timer fires, and real Qt never kills an active navigation, uses a sub-50 ms retry, routes a redirect through `BrowserSession`, or crashes real find/action/scroll callbacks. Add controllable fake ordering plus gating cases for active-load death, immediate retry, in-flight deactivation, state/token separation, protocol redirect, close/teardown during an active recovery token, and one non-read real callback.
